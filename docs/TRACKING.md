# Tracking sources

The customer and Pro connect to the same authenticated booking room. REST writes remain the source of truth; room events refresh booking/chat/add-on data immediately, with REST polling as recovery (30 s, or 5 s while the socket is down). Each user also holds a personal `user:<id>` room for changes to any of their bookings and bulletins. A socket silent for 25 s, or any socket when the app returns to the foreground, is replaced. Without a production road route the marker glides between real fixes. Socket URLs contain a one-use, 60-second ticket, never the bearer session. Connections renew before their five-minute limit.

Real location uses the Capacitor Geolocation plugin with precise-location permission. An online foreground Pro keeps the dispatch location fresh; while travelling, fixes also stream to each assigned EN_ROUTE booking. Refreshing location never changes the availability flag. Selecting or accepting a queued booking does not close the current travel booking’s stream. Native watches stop when no longer online/travelling or when the app backgrounds; keep both demo phones awake and the Pro app in front.

A route is fetched once per travel source/order from the first fix to the chosen booking pin using the OSRM demo driving router in development. Geometry uses OpenStreetMap data, © OpenStreetMap contributors, ODbL. A licensed/self-hosted routing provider must be configured before production routing; the public demo router is not a production dependency. When routing is unavailable, retain the actual GPS position and hide the guessed route line. Incoming positions snap to the remaining street polyline and interpolate between fixes. After 20 seconds without a fix, show “Reconnecting…” and keep the last position. Arrival uses the actual booking pin, never a sample endpoint.

For indoor rehearsal, enable **Demo: simulate route** on the Pro dashboard or job page. It streams the embedded Tuguegarao street geometry through the same socket. The customer’s toggle may stay off: the received simulated source is labelled explicitly. The API accepts simulated GPS only for demo bookings outside production. This fallback cannot advance a live booking, mark arrival, reveal a PIN or release money. The Pro still taps the status controls. A reload returns to live GPS so the fallback is always explicit.

Camera/location permission strings are in iOS Info.plist; the Geolocation SPM plugin is synced. Android manifest and packaging are part of F1. Native Android/iPhone GPS and same-Wi-Fi installation still need device rehearsal; browser/Miniflare verification is not evidence of physical-device success.
